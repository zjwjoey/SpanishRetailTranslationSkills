## 1. 为什么做这个项目

欧洲零售商品数据的中文处理，不只是逐词翻译。Action 的商品名称通常很短，而 Amazon.es 可能在一个标题或卖点字段中混入品牌、型号、规格、重复描述、页面残留和平台元数据。简单地全文翻译，会带来误译、虚构商品属性、规格错位、重复信息及不必要的成本。

本项目利用已有的 **Action / Amazon.es 西班牙语原始商品数据与中文历史译文**，研究和改进现成开源翻译 Skills 的方法，并将可验证的商品领域经验沉淀到五个专业 Skills 中。

这里的“训练”特指 **基于审核案例迭代 Skill 指令、术语知识、分类规则、审查规则和评测集**，**不涉及模型权重训练或微调**。

### 核心目标

1. **翻译正确**：准确识别商品主体、用途、材质、规格、数量和型号，不编造原文没有的事实。
2. **符合中文零售表达**：输出简洁、自然、便于研究与比价的商品名称、规格和描述。
3. **有选择地翻译**：在长字段中区分商品事实、品牌/型号、平台元数据、重复文本与网页噪声。
4. **审查可追溯**：任何删减、去重、保留和译文修正，都能对应原始字段及原因。
5. **持续提升质量**：只从可信样本和人工确认的错误中提炼知识，通过独立测试验证优化。
6. **适应大货盘**：针对约 5,500 SKU 等规模采用知识复用、批量并行、增量处理和分级审查，不强制每条商品启动多个子智能体。

### 当前明确不做

- 不支持德语、法语、波兰语等其他语言；多语言不是首期目标。
- 不开发独立翻译引擎、数据库、Web、API、EXE 或完整采集系统。
- 不修改 ActionSKUTracker、AmazonESBestseller 的采集主程序。
- 不依赖某个外部收费翻译 API，不进行模型微调。
- 不把未核验的历史中文译文直接视为标准答案。
- 不为了压缩字符数而删除关键商品事实，也不在未经授权时公开上传完整货盘。

## 2. 五个专业 Skills（唯一正式交付范围）

| Skill | 核心职责 | 关键边界 |
| --- | --- | --- |
| `es-retail-category` | 理解原始分类及商品用途，给术语判断提供类目语境，提出统一中文研究分类建议 | 保留平台原始分类，不擅自改变商品事实 |
| `es-retail-terminology` | 识别专业词、标准译法、品牌、系列、型号、技术代码及应保护的表达 | 不负责删减商品内容，不以“无需翻译”为由丢弃型号 |
| `es-retail-reviewer` | **翻译前**审查字段价值与冗余；**翻译后**审查译文事实、遗漏、虚构和筛选结果 | 不独立改写已批准术语；发现冲突标记复核 |
| `es-retail-translator` | 按照审核后的信息和术语、分类语境翻译商品名称、规格、描述 | 不擅自补充原文未证实的属性，不自行宣布审校通过 |
| `es-retail-learning` | 从人工确认的纠错记录中归纳错误模式和技能优化建议 | 不能自行覆盖正式知识库或发布新版本 |

**数量约束：正式专业 Skills 始终为五个。** Codex 主智能体通过仓库根目录 `AGENTS.md` 及开发任务指令进行协调，**不是第六个 Skill**。Codex 子智能体是执行者，**不等同于 Skill 数量**。

### 职责冲突如何解决

- **分类**回答“这是什么类型的商品、处于什么语境”。
- **术语**回答“这些词代表什么、怎样翻译或原样保护”。
- **前置审查**回答“哪些事实进入中文研究描述，哪些去重或转为独立元数据”。
- **翻译**根据已确认的输入生成中文。
- **后置审查**重新对照完整源文检查翻译和前置筛选是否正确。

优先级：**源文事实与可追溯性 > 已确认术语/不可翻译标识保护 > 内容筛选规则 > 中文表达润色**。意见冲突时进入 `REVIEW_REQUIRED`，不静默覆盖。

## 3. 目标工作流

```text
Action / Amazon.es 原始西语数据
               │
       数据来源与商品标识核对
               │
      ┌────────┴─────────┐
      ▼                  ▼
 Category Skill    Terminology Skill
      └────────┬─────────┘
       统一类目语境与术语
               │
       ┌───────┴────────┐
       │ 是否有超长字段、 │
       │ 重复/平台噪声？  │
       └───────┬────────┘
          是   │   否
          ▼    │
 Reviewer · SOURCE_AUDIT
          │    │
          └─┬──┘
            ▼
      Translator Skill
            │
   完整字段基础核对 / 风险分级
            │
 Reviewer · TRANSLATION_AUDIT
     （高风险深审、其他按规则抽检）
            │
      通过 / 待复核 / 失败
            │
    中文商品研究结果 + 审计记录
            │
       人工确认纠错后
            ▼
       Learning Skill
       （离线提出改进）
```

分类和术语可**并行初步识别**，但有歧义时需要合并类目语境后确定术语；**前置审查依赖二者的结果，不能与其完全独立地给出最终结论**。

### Reviewer 的两种模式

**`SOURCE_AUDIT`（翻译前）**：识别并标注源文中的有效商品事实、重复片段、品牌与型号、技术编码、平台指标、网页展示残留、冲突和截断。对普通短字段可跳过复杂筛选；对 Amazon 超长字段重点执行。

**`TRANSLATION_AUDIT`（翻译后）**：在独立审查上下文中对照**完整原文、前置审查记录与中文结果**，检查商品主体、包装数量、材质、参数、重要信息遗漏、虚构信息、术语一致性，以及是否误删有效事实。

前置审查的建议动作：

| 标记 | 含义 | 处理原则 |
| --- | --- | --- |
| `TRANSLATE` | 需要中文表达的商品事实 | 保留原文定位，进入翻译 |
| `PRESERVE` | 品牌、型号、系列、ASIN 等不可随意改写内容 | 原样保存，可关联独立字段 |
| `METADATA` | 排名、评分、评论数、发布日期等平台信息 | 按研究需求存储，不硬塞进商品描述 |
| `DEDUPLICATE` | 已核实完全重复的片段 | 仅从目标描述去重，保留来源 |
| `EXCLUDE_FROM_DESCRIPTION` | 网页噪声或与商品描述无关的内容 | 不进入目标描述，不等于删除源数据 |
| `REVIEW_REQUIRED` | 语义不明、字段冲突或来源截断 | 停止自动定稿，转人工复核 |

每项处理应记录 `source_field`、可定位原文片段、动作、理由和结果字段。**“不翻译”不等于“不要保存”。**

### 示例：Amazon 长字段

以 `Philips OneBlade 360 / QP2734/30` 相关属性为例：

- `PHILIPS`、`OneBlade 360`、`QP2734/30`：品牌、系列与型号，**保护并保留**。
- `2 Cuchillas 360`、`Peine-Guía Ajustable 5 en 1`、`60 minutos`：真实配置和性能，**应翻译并保留**。
- 重复出现的完整标题、重复品牌、同义字段：先核对是否确属重复，再**去重显示**。
- `ASIN`、GTIN、排名、评分：按需求保留为**商品标识或平台研究元数据**，通常不写入商品功能描述。
- `Ver más` / `查看更多`：识别为展示残留，**同时检查是否表示被截断**。
- 对“刀片数量/包装内容”之间的冲突：不得擅自取其中一个值；需要标记待复核。

## 4. 历史数据如何用于“训练”

数据来源：Action 的西语与中文对照、Amazon.es 的西语与中文对照。**历史中文版本可能存在错译、原文污染、规格错误或数据错位**，必须先核验。

### 数据准入状态

- `RAW`：未审核原始记录。
- `CANDIDATE`：已对齐但未确认的候选案例。
- `VERIFIED`：经过可信人工核验，可作为参考答案。
- `REJECTED`：已确认错误的译文。
- `SOURCE_ISSUE`：西语源文缺失、污染或事实异常。
- `ALIGNMENT_UNCERTAIN`：SKU/ASIN/变体关系无法确定。
- `REVIEW_REQUIRED`：需要人工复核的翻译或筛选争议。

**AI 自评不自动产生 `VERIFIED`。** Action 使用可靠 SKU 和快照字段对齐；Amazon 需要关注 ASIN、Parent ASIN、子体变体及不同来源快照，不能靠行号配对。

### 训练 / 优化 / 盲测三重隔离

| 数据用途 | 建议配比 | 访问权限与用途 |
| --- | ---: | --- |
| `train` | 60% | 术语、规则、正确案例、错误案例的知识提取 |
| `validation` | 20% | 优化 Skill，反复测试与修订 |
| `holdout` | 20% | 冻结候选后独立验收，不向优化组暴露答案 |

第一轮**目标**：Action、Amazon 各准备约 300 条经确认的样本，共约 600 条；这不是当前已具备的事实，更不是强制凑数指标。应按实际有效数据量和类目覆盖情况调整。

防泄漏：按同款商品、父子变体、重复标题、相同商品不同快照及跨平台近重复内容进行**分组划分**，不可将同组记录分别放入训练和盲测。盲测答案须处于优化组实际无权访问的位置；**同一共享工作区下的普通目录不构成真实隔离**。

### 知识升级循环

`人工确认案例 → 术语/规则候选 → 独立优化 → validation 回归测试 → holdout 验收 → 发布 / 回退`

Learning Skill 只提出候选修改。正式知识升级必须经过审核和回归测试，不能把一次个例修正升级成全类目绝对规则。

## 5. Codex 多子智能体的开发与生产安排

### 开发阶段：按专业能力分工

主智能体制定统一契约、分配互不冲突的工作范围，子智能体分别负责上游研究、Action 数据核验、Amazon 数据核验、术语/分类知识、翻译与审校 Skills、评测和独立复审。独立工作可并行；依赖任务顺序执行。

- 各子智能体使用独立工作区、Git worktree 或明确的文件所有权，**不得并发改动同一正式文件**。
- 五个 Skill 具有独立触发范围、输入输出规则和专门评测，不把五个 Skill 当成五个永远同时运行的 Agent。
- `AGENTS.md` 负责协调机制，不作为新的专业 Skill 发布。

### 使用阶段：按商品批次分工

对于约 5,500 SKU 的完整货盘，**不得为每条 SKU 固定启动五个 Agent**。建议初始使用 **3 个批量工作子智能体 + 按需独立 QA 子智能体**，再由实际运行数据决定并发数；这只是起步配置，并非承诺的性能。

1. **已核验且原文与相关规则未变化**：优先复用，不重复生成。
2. **普通短名称**：按类目复用知识包，批量翻译，不强制复杂前置审查。
3. **歧义商品**：补充分类/术语消歧，再翻译。
4. **Amazon 超长字段**：执行 `SOURCE_AUDIT`，再翻译与重点审查。
5. **来源冲突、规格矛盾或审查不通过**：独立复核，不强制输出确定译文。

首轮用约 **100–200 SKU** 做试运行，测量实际时长、Token、错误率、人工复核量与批次稳定性；再据此决定批次大小（例如普通商品先试 40–60 SKU/批，长字段先试 5–15 SKU/批）。这些数字均为**实验起点，不是已验证吞吐量**。

所有商品应进行标识对齐、字段完整性、数字/单位保护等基础检查；**风险分级深审与抽样审查不能被误称为所有商品已经通过全面语义人工审核**。

## 6. 质量标准与验收

评测至少覆盖：

| 维度 | 检查内容 |
| --- | --- |
| 商品主体 | 中文是否准确表达实际商品 |
| 规格事实 | 尺寸、容量、材质、数量、单位及包装配置 |
| 信息完整性 | 是否遗漏重要卖点或关键参数 |
| 反虚构 | 是否加入源文不存在的事实 |
| 术语一致性 | 相同语境下的同类商品命名是否一致 |
| 分类语境 | 商品类型、平台原类目与中文研究类目是否合理 |
| 长字段审查 | 冗余识别、有效事实保留、型号/品牌保护、冲突检测 |
| 可追溯性 | 每项删减与译文修改是否能对应源片段 |
| 效率 | SKU/批次耗时、Token 消耗、缓存复用和复核量 |

错误分级：`P0`＝主体/关键规格错译、商品错配、虚构重要属性等严重错误；`P1`＝用途和重要属性翻译错误或遗漏；`P2`＝不影响事实的表达与格式问题。

采用**普通 Codex 基线、合法可运行的上游工作流基线、本项目 Skills 候选版本**进行同样本对比。区分 Action 与 Amazon 指标，并记录实际样本量和评测环境。

**发布门槛（计划）**：结构与商品标识检查全部通过；正式保留样本中不出现已知未处理的 P0；核心质量指标不低于基线、重要指标有可复核改进；不存在未解释的明显回归。若样本不足或盲测泄漏，只能标记**候选版本**，不得宣称生产级验证完成。

建议每次报告：已核验样本数、P0/P1/P2 分布、误删重要信息案例、术语冲突、人工改动率、平均成本与尚未解决的阻塞。

示例任务（以下仅为**未来使用方式示意**，不是当前已可执行的功能）：

```text
使用本仓库的西班牙零售商品 Skills，审查指定 Action 西语货盘。
```


```text

报告商品主体、规格、有效信息保留、P0/P1 错误、Token 及人工复核量。
```

## 11. 项目成功的判定

项目成功**不是**创建五个空的 `SKILL.md`，也不是翻译完 5,500 个 SKU。

真正的交付标准是：**五个可独立调用、职责不冲突的专业 Skills；可靠的西中商品知识来源；明确的数据隔离与质量审查机制；真实的基线对比证据；以及能够按批次高效处理大货盘的可复用工作方法。**

准确性优先，效率次之；任何加速都不能以丢失重要商品事实为代价。
