# 第一轮候选调优前后对照协议

状态：协议预登记；结果尚未运行。范围：24 件真实新商品，Action 12 件、Amazon 12 件；对照冻结前版本与本轮候选版本。本文件由未读取本轮候选知识、商品选择或生成输出的协议审查上下文编制。

## 1. 版本与输入冻结

运行前记录并冻结 baseline 与 tuned 的 Commit（有未提交候选时附完整文件清单、逐文件 SHA-256、快照路径）、公共契约版本、知识版本和实际加载路径；冻结后禁止改写同一次尝试。保留原始输出，修复或重跑写入新 attempt，不覆盖旧证据。

选样协调者在生成前固定 24 件清单及完整源字段 SHA-256，排除已用于本轮规则提炼的 60 件商品及已知同 SKU/ASIN、多快照、父子变体、跨平台同款与近重复商品组。关系证据不足的记录标记可能污染，不以仅换日期视作新商品。公布选择方法、排除方法、平台/类目/风险分布；不能在见到输出后替换难例。不得为凑数量改写或合成真实源文。

两臂读取完全相同的纯西语原始输入、稳定标识与原始源字段。合理英文品牌、系列、型号代码不算英文主体；完整英文主体不进入 es-ES 比较。生成者不能读取历史中文、本轮 60 件审核答案、新商品人工/AI答案、另一臂输出或本协议评审结论。生成前保存输入文件 hash 与 manifest。外部资料不作为某一臂的额外输入；另行补证只能在评审时记录为补充证据，并区分原输入是否支持。

## 2. 执行与输出

baseline 与 tuned 各在一个全新上下文处理相同 24 件，不能由同一上下文先后切换提示词充当独立运行。以整批而非每 SKU 固定启动五个 Agent；五个既有 Skills 按依赖、风险按需使用。两臂模型、设置、工具可用性、完整源输入和任务指令尽量一致，只改变预登记的 Skill/候选知识版本。无法读取的模型设置写 unknown，不声称条件完全相同。

每件输出必须至少包括：
- 不变的 item_id、platform、product_id、source_snapshot/hash 或完整源引用。
- 中文名称、规格（有序 key/value）、研究描述；平台类目翻译与建议研究类目、商品主体/用途语境分开。
- 品牌、系列、型号、ASIN/代码等保护原串及定位，兼容关系不得变为生产品牌或商品主体。
- 源问题、冲突槽、截断与不确定事项；无歧义事实继续输出，问题仅局部隔离。
- 源审动作账本及事实/字段对应证据：精确 source_field、source_span.quote、重复出现次数，能回查原输入。无前审应明确 skip_reason。
- 运行/数据状态分开；译者输出为 TRANSLATION_CANDIDATE/REVIEW_REQUIRED，不能自签 PASSED/VERIFIED。

记录每臂起止时间、实际耗时（仅可靠时钟差）、实际模型（未知为 unknown）、加载的文件及 hash、工具方式、输入数/输出数/唯一身份数。Token、费用、成本不可取得一律 null；不能以字数、估算吞吐或预设单价代替实测。

## 3. 独立审查单位与证据

两个输出全部完成并冻结后，由未参与生成的独立审查上下文读取完整原文、源审账本与两臂结果。可将臂名映射为 X/Y 降低偏好，但共享目录和可见版本差异不构成技术隔离，不能宣称正式双盲。逐件审查全部 24 件，不用抽检替代本轮覆盖。译者说明仅是被审查对象，不作为正确性的证据。

审查维度：
1. 商品主体与用途/研究分类是否忠于源文。
2. 数值、单位、尺寸轴、单件/套装层次及包装件数是否保留，数值归属是否正确。
3. 品牌/系列/型号等保护标识与兼容关系是否完整、归属是否正确。
4. 是否虚构、扩写无依据事实，或遗漏关键事实；是否错误去重/过滤独有事实、混入平台元数据。
5. 是否识别真正的同一语义槽冲突、保留双方证据并局部隔离；是否将不同部件/单位/参数误判冲突。
6. 是否不必要地阻断明确字段或整件商品；是否把所有译者的 awaiting_post_audit 状态误当源冲突。
7. 证据字段、精确引文、出现次数及目标路径是否可定位；不能引用实际为空的字段。

每项 finding 保留 item_id、arm、维度、severity、source_field/quote、target_field/quote、issue_key、判断与依据、确定性（CONFIRMED_AI_FINDING / UNCERTAIN / UNRESOLVED_DISAGREEMENT）。发现源文自身问题单独记录，不自动计译文错误。未经人工确认，AI 已有依据的判断仍不升级为人类标准答案。

## 4. 问题计数与固定分母

一项独立语义错误根因计一次 issue，issue_key = item_id + 语义事实槽/标识 + 错误根因。相同错值出现在名称、规格、描述时合并一项，列出全部受影响字段；独立事实槽确有独立错误才分项。每 issue 取最高严重度，不能同时计 P0 和 P1。同一错误跨维度展示也只计一次。

逐件记录 P0/P1/P2 数、总确定问题数、未决数以及是否存在至少一项确定 P0/P1。总确定问题数只包含 CONFIRMED_AI_FINDING；不确定或评审分歧不得计作确定错误或确定修复。未评字段明确排除，缺输出或身份错配不能从分母悄悄剔除。

分别给 Action（计划 N=12）、Amazon（N=12）与合计（N=24）：
- 完整产出覆盖率 = 有身份匹配完整输出件数 / 固定计划商品数。
- 存在至少一项确定 P0/P1 的商品数 / 实际逐件完成审查数；同时列计划数、漏审数。
- P0/P1/P2 确定 issue 数；每件问题数 = 该等级确定 issue 数 / 实际完成审查商品数。该比值可能大于 1，不能称准确率。
- 同一商品配对问题变化：已解决、新增、仍存在、仅改写、不确定/未决；仅双方输出和完整源均被审查的配对进入差值分母，并给出缺配对数。
- 事实、字段或标识层面的比率仅在评审前完成共同原子清单且逐一核查时计算，给出实际原子/字段分母；否则只报告可定位问题计数，不事后估算分母。
- 人工确认数、人工修改率、正式准确率均不可用；人工确认数若无确认明确为 0，其他写 N/A。

数字字符串一致不代表单位语义正确；不使用答案逐字匹配、BLEU 或期望中文文本命中率代替上述审查。

## 5. 严重度与 blocker

P0：身份/主体错配，关键型号、件数、关键尺寸/配置错误，虚构重要属性或误删关键事实。
P1：用途、核心属性、术语/分类造成实质研究误判，重要信息遗漏。
P2：不改变事实的自然度、格式与风格问题。

必要 blocker：身份不能确定、关键源不可获得，或互斥关键配置无法定位到当前变体时，阻止该冲突槽定稿；身份/主体不明可阻止整件定稿。源冲突本身不是译者错误；猜一个值冒充确定事实才计错。局部槽存疑但主体及其他事实明确时，保留明确事实，不能把整件置空。

不必要 blocker：源证据明确且无同槽矛盾，却仅凭缺少官网、常识疑虑、一般营销词或不同部件参数暂停全部明确内容；须列出本应保留的源事实才计确定问题。一般 REQUIRES_REVIEW/awaiting_post_audit 工作流状态不是 blocker，不能以待审商品总数推断阻断率。

## 6. 差异判定与停止条件

改善只限于有源证据、同一 issue 槽的确定纠错；表达不同但事实等价记等效，不算质量提升。不确定、未决分歧、评审新增猜测不计确定改善。分别记录 corrected/new/persistent，不用总问题下降掩盖新增 P0。

出现 tuned 的关键配置倒退、身份错配或未解决 P0 时，停止候选合并；保留候选与回退证据，先修复并以新 attempt/新样本复核。未解释的明显 P1 倒退也阻止升级。该门槛即使总问题减少仍适用。必要的字段隔离不能因降低 blocker 数而移除。

即使未观察到确定倒退，也只得出“本次 24 件、一次运行的 AI 行为观察”；模型随机性、样本不足、无人工标准答案和隔离不足限制因果推断。继续扩大独立商品与人工核验，再讨论正式升级；不得宣称生产级、正式准确率提升、全量 5500 SKU 可用或通过 V1。

本次 baseline 指现有专业 Skills 冻结前版本，tuned 指本轮候选；不能冒充普通 Codex 或原始 GitHub 翻译方法。普通 Codex、合法可运行上游若未实际运行，分别标 NOT_RUN/NOT_COMPARABLE，不编造三方比较。

## 7. 数据与知识门禁、交付

本轮属于候选规则提炼和新商品开发性评估。此前 AI/官方资料补证不等于人工 VERIFIED；不建立正式 Train/Validation/Holdout，也不把本轮新样本称作受控盲测。正式字段 human_confirmation 保持真实，dataset_split 保持 unassigned；不确定字段排除出知识提炼，但保留排除原因、源文与范围，不覆盖原始货盘。

保留 Learning 的人工确认 gate：没有人工确认纠错时其正式训练结论为 EVIDENCE_BLOCKED；主智能体可审查候选流程改善，不能冒称 Learning 已从可信人工样本学习或把候选写入 approved。

应交付冻结 manifest、24 件只读输入与 hash、两臂原始输出及运行日志、逐件评审 findings、配对汇总、问题/未决清单、候选改动/回退路径。私有原文及逐件资料留在忽略目录；可提交协议和不含敏感源文的汇总。协议发生修改须新版本并说明是在运行前还是看到输出后变更，不追溯改写判定口径。
