# 三臂 native V2：运行前冻结协议

**必须在首次真实候选生成前冻结协议和 prompt 的原文字节 SHA256。** 该版本是新的工程诊断，不是统计显著性、人工 Gold 标注或正式生产发布。

## 1. 独立比较对象
| 组 | 用户业务任务 | 专业提示词 | 五个 Skills 文件 | 加载方式 |
|---|---|---|---|---|
| A | 与 B/C 完全相同 | 无 | 不可见 | 无 |
| B | 与 A/C 完全相同 | 固定专业追加清单 | 不可见 | 普通文本提示 |
| C | 与 A/B 完全相同 | 无 | 可见 | **Codex 原生发现、仅在需要时读取** |

三臂使用同一真实数据、字段 Schema、任务边界、模型/思考等级、CLI 版本、sandbox、网络状态、上下文重置策略、可用调用次数、自检轮次。B 唯一差异是固定追加的专业提示词；C 唯一差异是 native Skill 资源与对应发现能力。禁止把 B 的专业清单加到 A/C。五个 Skill 不是五个必须对每 SKU 启动的 Agent；Learning 因人工 Gold 为 0 正常不触发。

## 2. 样本与冻结
- 仅选新的 24 个真实 SKU：Action/Amazon/IKEA 各 8，平台内 4 ordinary 和 4 complex；绝不从历史已曝光30件当作新样本。A/B/C 按相同顺序与批次运行，并交错三臂执行顺序减少顺序偏差。
- 从只读 Action/Amazon/IKEA 西语源挑选；检查正文西语而非只看标题，保留完整字段、商品身份、变体、Parent ASIN/IKEA family、源码位置及 source_sha256。
- 整合所有旧评测（包括 V1 30、历史 SKU、失败/备选/回归、同款/变体/系列/跨平台/多快照近重复组）为排除账本。不完整则报告 NOVELTY_UNVERIFIED、风险范围、候选筛选规则；绝不声称 sealed holdout。
- 复杂度必须在看翻译前冻结。基于源正文长度、字段数、规格数字/单位数、兼容枚举长度、否定/限定条件、材质/部件角色、源冲突数进行平台内相对排序。每平台选择 4 个较简单与 4 个较复杂且尽可能覆盖不同商品类目；同系列不能拆到两个选样组。每个商品记录原始特征及分层理由，事后不能换难例。
- 输入、曝光账本、prompt、Skills、contracts、相关 refs、approved manifest、CLI 配置的 hash 与选样清单在生成前冻结。所有 raw 数据位于 ignored local/ 下，不上传公开 GitHub。

## 3. native 预飞行（硬门禁）
先查询真实安装版 `codex exec --help` 和版本；用一个明确标记 synthetic 的西语测试商品，在 repo 祖先目录之外创建工作区。A/B 必须无本仓库或全局同类 Skills，C 从冻结版复制五个入口及其 references、contracts 和 approved manifest；不复制整份根 AGENTS 到 C 用来偷偷增加专家规则。若必须有 AGENTS 作发现入口，采用三臂相同的中立说明，额外差异必须登记。

对 C 用标准用户业务任务演练客户端发现。保留 `SKILL.md` 和适用 reference **真实文件读取的可核验宿主日志/命令与文件路径**、CLI 原始 JSONL、触发方式。仅目录存在、CLI metadata 出现或模型自称已读，均不构成实际读取证据。不能为了通过门禁在正式任务中粘贴全文或在所有样本上强制完整读五个 Skills；如 native 不可达，C=NOT_RUN，不可偷换为 C=FULL_TEXT_INJECTION。

之前 V1 因 read-only 策略遇到文件读取阻断。修复方法是只在被授权的隔离工作区开启安全读取权限、按当前 CLI 真实参数重试 synthetic 预飞行；不提升无关写入/网络权限、不断改模型、不能因此更改三臂共同模型设置。若仍失败，停止。

对 A/B 验证 Skills 不可见并明确记录环境/全局配置差异。原则上三臂从 repo 外部工作区执行，临时目录隔离，任务 prompt 不暴露到正式仓库根的 AGENTS 继承链。真实可用权限若无法等价，标 NOT_COMPARABLE。

## 4. 正式生成
- A/B/C 使用相同中立 `COMMON_TASK` + 统一 Output Schema。B 额外加载一次 `EXPERT_APPENDIX`；C 只从 native 机制读取必要 Skills；C 不追加专家提示词。
- 每组每个商品一次首次生成 + 相同的自检机会，建议复杂商品单SKU上下文、普通最多2SKU一批；三个组完全同样的边界/机会。不能看到 QA 后重写首次结果来提高分数。
- 故障/截断时冻结首次 attempt、错误与 token；按 **预定通用失败重试规则**重试全部有同类型错误的臂，不因 C 表现差而临时特殊照顾；首次成功率单独报告。
- 保存所有原件、输出 source_hash、临时上下文/任务标识、native 文件读日志。记录模型请求参数和服务端可观测情况；底层未知明确 unknown。

## 5. 独立复核
- QA 在不知道 A/B/C 的条件下，先完整阅读所有 24 条西语源文，形成逐商品事实原子清单并冻结；才解锁随机 X/Y/Z 译文。事实清单需区分主体、用途、数值与轴、包装数量/代际/计价角色、保护标识、兼容对象全列表、材质与部件、否定/限制、类目、数据污染与未知源槽。
- 同一事实遗漏同时影响多个中文字段，只计一个根因；事实已经保存到其他正确字段不算遗漏。源字段不明确的内容应列 SOURCE_ISSUE/UNCERTAIN，不能当译者错误。审查初判、撤回、裁定和证据同时保留。
- P0 = 身份/主体或关键配置错误、严重信息虚构/误删；P1 = 关键属性、兼容/条件/数量/材质错译或实质遗漏；P2 = 风格/结构/非实质残留。AI 确认不等于人工确认。记录每组每平台每难度的影响商品数、完整审读率、事实覆盖与未审。
- 人工环节须对盲化版本逐项标注：edit_seconds、修改字段数、实质性修订数、P0/P1/P2 确认、确认/撤回原因。可让人工审校24×3全部；资源不足时必须预先冻结分层人工子样本并将其余报告为 N/A。三臂先后顺序随机平衡，披露同一审校者看到同款三份导致的学习效应。
- 对没有人工确认的数据，仅写 AI-observed differences；不写 accuracy、人工返工减少率或 V1 PASS。

## 6. 效率 / ROI 与停止条件
Token = 原始日志中实际 input、cached-input、output 及 Skill 文件工具调用产生的上下文开销；除非有真实价格记录，否则费用 N/A。延时既分开报告每调用墙钟时间之和，也报告同等条件下的关键路径时间；不能从 batch 并发总和猜测生产吞吐。人工时间只用计时记录。不因 C 获得更多信息就把 token 膨胀归罪于技能本体；同时也不能把额外成本忽略。

必须分别比较：A→B（专业提示词的贡献），B→C（Skills 相对专业提示词的贡献），普通/复杂及 Action/Amazon/IKEA。重要维度优先级：P0/P1 和事实覆盖 > 可证人工返工 > 实际总输入/输出 token 与耗时 > P2 文风。如果 C 与 B 重要质量持平又没有可证人工/效率收益，建议精简规则，不再靠增加翻译批次“训练”；如果 native 门禁未通过，则停止下结论、只处理原生触发和读取链路。

这些仅是本次小样本的诊断决策，不代表统计显著或最终泛化。禁止将 AI 审查提案自动升级 knowledge/approved、修改源数据、跨项目泄漏或自动合并。
